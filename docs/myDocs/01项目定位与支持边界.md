# 01 项目定位与支持边界

## 项目解决什么问题

这是一个用 C++20 实现的小型 HTTP 服务器。它把“客户端发送 TCP 字节”转换成“读取静态文件或执行用户 API，再返回 HTTP 响应”，用于学习服务器内部的工作过程。

主要机制都在仓库内实现：socket 封装、HTTP 请求解析、路由、线程池、JSON、日志和配置。它适合学习网络编程、资源管理、并发和模块测试；当前能力定位是教学及作品展示。

示例网页位于 [public](../../public)，首页使用 [script.js](../../public/script.js) 请求用户列表并提交新用户。用户信息保存在进程内存中，每次新建 `Server` 都从 Alice 和 Bob 开始。

## 平台支持应如何理解

| 平台 | 源码依据 | 本次结论 |
| --- | --- | --- |
| Windows | `_WIN32` 分支使用 Winsock2、`WSAStartup`、`closesocket`；CMake 链接 `ws2_32` | 明确实现的目标平台；包含 MSVC 编译选项，也可见本地 CLion/MinGW 构建配置 |
| Linux | 非 Windows 分支使用 POSIX socket、`close`、`errno`、`MSG_NOSIGNAL` | 明确实现的另一目标平台 |
| macOS / 其他类 Unix | README 给出类 Unix 构建命令，但实现统一落入非 Windows 分支 | 本次未确认兼容性，尤其要复核 `MSG_NOSIGNAL` 等平台差异，不能由“有 POSIX 分支”推定全部可用 |

本次没有执行任何平台的构建或运行验证。本地存在构建缓存、可执行文件，只说明此前产生过这些文件，不能证明当前源码构建通过。

入口依据：[CMakeLists.txt](../../CMakeLists.txt)、[Socket.hpp](../../src/net/Socket.hpp)、[Socket.cpp](../../src/net/Socket.cpp)。

## 已实现的功能

| 能力 | 实现和边界 |
| --- | --- |
| TCP 服务 | IPv4，默认监听 `127.0.0.1:8080`；绑定地址和端口可配置 |
| HTTP 请求 | 接受文本形式的 HTTP/1.1 和 HTTP/1.0，请求目标必须以 `/` 开头 |
| 方法 | `GET`、`POST`、`PUT`、`DELETE`、`HEAD`；方法名按大写文本识别 |
| 请求分片 | `RequestParser::consume()` 可多次接收字节片段；长度由 `Content-Length` 确定 |
| 长连接 | HTTP/1.1 默认保持；HTTP/1.0 默认关闭；支持下一请求剩余字节的传递 |
| 路由 | 固定路径、`{id}` 路径参数、方法不匹配的 `405 + Allow`、静态文件兜底 |
| 静态资源 | `GET/HEAD`、目录的 `index.html`、无扩展名 URL 补 `.html`、MIME 判断 |
| 用户 API | 内存用户的列表、查询、创建、替换、删除；按名字子串过滤 |
| 系统 API | `/api/health`、`/api/benchmark` |
| 并发 | 固定工作线程，连接任务进入有容量上限的队列；提交失败时响应 503 |
| 日志和退出 | 文本日志、可选追加日志文件、SIGINT/SIGTERM 触发停止流程 |
| 测试设施 | 自制测试框架；源码中有 86 个单元用例和 15 个集成用例 |

`HEAD` 复用 `GET` 路由并在正常响应发送阶段省略正文。HTTP/1.0 请求虽然可解析，响应状态行仍由序列化器统一写成 `HTTP/1.1`。

## 默认限制

| 项目 | 默认值 | 来源 |
| --- | --- | --- |
| 请求头区域，包含请求行及结束分隔符 | 8192 字节 | `Config::maxHeaderBytes` |
| 请求正文 | 1 MiB | `Config::maxBodyBytes` |
| 请求目标，包含查询串 | 2048 字节 | `ParserLimits::maxTargetBytes`，未暴露配置项 |
| 单个静态文件 | 32 MiB，超过才拒绝 | `StaticFiles.cpp` 常量 |
| 单连接请求数 | 100 | `Config::maxRequestsPerConnection` |
| 等待队列中的连接任务 | 256 | `Config::maxQueuedConnections` |
| 请求收取停顿时间 | 5000 ms | 每次收到数据会重新计算期限 |
| 后续请求的空闲等待 | 15000 ms | `keepAliveTimeoutMs` |
| 工作线程 | 示例配置为 8；纯代码默认值为 0，即自动选择 | 详见 [06配置系统](06配置系统.md) |

这里的限制不等于进程内存上限：正文、解析缓存、文件内容和响应序列化结果可能同时存在，多个连接也会同时消耗内存。

## 当前不支持的内容

- HTTPS/TLS、HTTP/2、HTTP/3、反向代理、WebSocket 升级。
- 请求的 `Transfer-Encoding`，无论其具体值为何，存在该头就返回 501；响应也没有 chunked 编码。
- `OPTIONS`、`PATCH`、`TRACE`、`CONNECT` 等方法，解析阶段返回 501。
- `Expect: 100-continue` 握手、通用中间件、虚拟主机选择和完整的 HTTP 协议实现。
- 文件上传、multipart 解析、磁盘文件删除、目录列表、断点续传和 Range 响应。
- 文件流式发送、`sendfile`、压缩、ETag、条件请求；静态响应仅固定设置 `Cache-Control: no-cache`。
- 用户数据持久化、数据库、认证、授权、限流、按 IP 配额。
- epoll/IOCP 异步事件模型；空闲长连接仍占用一个工作线程。
- 配置热加载、完整的进程服务管理，以及已验证的同一 `Server` 对象停止后重启能力。

“已实现路径检查”也不等于所有路径场景都安全。自动追加 `index.html` 和 `.html` 后没有再次做 canonical 边界检查，详见 [15静态审查问题与改进方向](15静态审查问题与改进方向.md)。
