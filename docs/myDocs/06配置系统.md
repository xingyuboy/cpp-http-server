# 06 配置系统

代码入口：[Config.hpp](../../src/config/Config.hpp)、[Config.cpp](../../src/config/Config.cpp)、[main.cpp:73](../../src/main.cpp#L73)、[server.conf](../../server.conf)。

## 一条配置如何进入服务器

```text
Config 成员默认值
  → main 探测配置文件是否可打开
  → loadFromFile 读成字符串
  → parse 按行覆盖默认值
  → main 应用 --port / --root / --log-level
  → 移动 Config 到 Server::config_
  → 创建监听、线程池、静态处理器，并供每个连接引用
```

优先级是“命令行覆盖 > 文件配置 > 代码默认值”，但解析顺序同样重要：文件首先必须成功解析，才会轮到覆盖。文件里写 `port = abc`，即使启动时传 `--port 8080` 也会提前失败。

`main` 先用 `ifstream` 探测文件，失败时直接使用默认值；`Config::loadFromFile` 自身则在打不开文件时抛异常。这解释了“缺失文件的单元测试要求抛异常”，却不能据此认为“主程序指定缺失配置也一定退出”。

## 配置项总表

| 文件键 | 成员 | 代码默认值 | 当前校验或使用方式 |
| --- | --- | --- | --- |
| `bind_address` | `bindAddress` | `127.0.0.1` | 接受非空字符串；是否可解析、可绑定留到网络层 |
| `port` | `port` | 8080 | 文件解析严格限制 1～65535 |
| `document_root` | `documentRoot` | `./public` | 接受非空字符串；Server 构造时 canonical |
| `worker_threads` | `workerThreads` | 0 | 文件解析限制 0～512；0 自动选取 |
| `request_timeout` | `requestTimeoutMs` | 5000 | 解析为整数并转 int，最后要求大于 0 |
| `keep_alive_timeout` | `keepAliveTimeoutMs` | 15000 | 转 int，没有额外范围检查 |
| `max_requests_per_connection` | `maxRequestsPerConnection` | 100 | 转 int，没有额外范围检查 |
| `max_header_size` | `maxHeaderBytes` | 8192 | 转 size_t，没有先检查负数或有效上限 |
| `max_body_size` | `maxBodyBytes` | 1048576 | 转 size_t，没有先检查负数或有效上限 |
| `max_queued_connections` | `maxQueuedConnections` | 256 | 转 size_t 后只检查不为 0 |
| `listen_backlog` | `listenBacklog` | 128 | 转 int，直接传给 listen |
| `log_level` | `logLevel` | Info | 只接受四种级别的全小写或全大写形式 |
| `log_file` | `logFile` | 空，不启用文件日志 | 配置值须非空；相对路径相对于工作目录 |

时间单位是毫秒，大小单位是字节。示例 `server.conf` 把 `worker_threads` 设为 8，**与结构体中的 0 不同**。未加载文件时不应把 8 当成默认线程数。

`resolvedWorkerThreads()` 的规则：显式值大于 0 就返回该值；否则读取 `hardware_concurrency()`，返回 0 时用 4，其他情况至少取 2。它没有把自动模式限制到文件参数的 512 上限。

## 文本语法和错误信息

每行按以下顺序处理：

1. 去掉两端空格、Tab、回车。
2. 从第一个 `#` 起截掉后续内容，再次去空白。
3. 跳过空行。
4. 找第一个 `=`，得到键和值，并各自去空白。
5. 拒绝空键、空值、未知键；根据键解析字段。
6. 全部读完后检查请求超时和队列容量。

数字先用 `from_chars` 解析为 `long long`，要求完全消耗输入。因此文件里的 `8080abc` 不会被当成 8080。

语法没有节、引号解析、变量替换、转义或包含其他文件。写 `document_root = "./public"` 会把双引号视为路径字符；路径中的 `#` 会被截断。同一键出现多次时，后面一次覆盖前面一次。

多数逐行错误使用 `config line N: ...`。最后的 `request_timeout must be positive` 和 `max_queued_connections must be positive` 不携带具体行号，因此不能说所有校验错误都有行号。

## 相对路径的真实基准

配置文件、静态根路径、日志路径都是相对于进程当前工作目录处理，代码没有把路径改为相对配置文件，也没有做可执行文件目录探测。

例如，从仓库根目录启动并指定 `--config configs/dev.conf`，其中的 `document_root = ./public` 仍指向仓库根目录下的 `public`，不是 `configs/public`。

`Config::parse()` 只是读出字符串。根路径可用性在 `StaticFileHandler` 构造时检查，地址解析和端口可用性在 `bindAndListen()` 检查，日志文件打不开则仅打印警告继续运行。

## 当前校验缺口

| 输入或调用 | 从代码推导的行为 |
| --- | --- |
| 文件 `port = 70000` | 抛 `ConfigError` |
| 命令行 `--port 70000` | `stoi` 后转 uint16_t，变为 4464；没有统一范围检查 |
| 命令行 `--port 8080abc` | `stoi` 没有检查消耗位置，可接受前缀 8080 |
| 命令行 `--port 0` | 可以进入绑定端口 0 的路径，区别于文件配置 |
| 文件 `max_body_size = -1` | 转为无符号大值，破坏原本预期的体积限制 |
| 文件 `max_requests_per_connection = 0` | 可解析；连接循环条件一开始为假，不处理请求 |
| 文件 `keep_alive_timeout = 0` | 可解析；实际 socket 等待行为还受平台影响，不能按正常超时语义使用 |
| 直接构造 Config 后写成员 | 绕过 `Config::parse()` 的全部文件校验 |

较大的整数转成 int 前也没有范围检查。建议把最终配置校验提取成独立步骤，让默认值、文件、命令行和程序化配置经过同一套验证；当前代码尚未这样实现。
